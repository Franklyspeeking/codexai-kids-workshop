# 九个课堂工具：手机优先重做

日期：2026-10-05。范围：本仓库公开 Demo；未发布到 VPS，未修改兄弟目录 course-products 和课堂起始 ZIP。

## 设计依据

重新设计的目标是让 9–14 岁孩子直接完成一项任务，而不是阅读一页功能说明。原版把日常使用、第二套工作台、维护、备份混在一个长页中，手机上重复、冗长且缺少明确主操作。

调研了以下产品的官方介绍，查看了 Structured、Finch、Wanderlog 的实际官网页面。以下是借鉴的交互原则；未复制品牌、截图或第三方素材，也未声称使用了这些产品的付费功能。

| 参考 | 采用的原则 | 应用到 |
| --- | --- | --- |
| [Structured](https://structured.app/visual-planning) | 以时间轴组织活动，直接在活动旁处理冲突 | 周末日程 |
| [Rooster Money](https://roostermoney.com/feature/chore-app-rooster-money/) | 家务、积累、奖励之间有明确因果关系 | 家务与零花钱 |
| [Opal](https://opalapp.com/) | 突出单个计时状态，减少启动步骤 | 屏幕时间；仅参考呈现，不提供设备封锁 |
| [Wanderlog](https://wanderlog.com/) | 方案、行程、预算与清单分工清楚 | 家庭出游 |
| [Finch](https://finchcare.com/) | 用小行动和鼓励推进习惯 | 习惯生长园；不做断签惩罚 |
| [StoryGraph](https://www.thestorygraph.com/?lang=en) | 以书与阅读兴趣组织信息 | 家庭借阅馆 |
| [Twine](https://twinery.org/) | 让选择连接到下一幕，创作和试读分开 | 分支故事剧场 |

选择：统一基本操作习惯，每课有独立功能布局。对比过“只换皮肤”和“九套完全不同导航”；前者不能解决重复流程，后者提高孩子换课时的学习成本。因此统一底部导航、弹窗、保存反馈，分别使用账本、时间轴、计时环、行程、周历、题卡、书架与故事舞台。

| 课程 | 主要流程 | 路径 |

## 界面和工程约定

- 360px 起以单列为基础；780px 起扩展为主内容加辅助区域。
- 手机底部导航保留三项主要任务与“更多”，考虑 safe-area；正文底部留足空间。
- 按钮最小高度 44px，主要输入字号 16px；键盘焦点可见；弹窗有标题、关闭按钮和原生焦点管理。
- 纸张底色、低饱和主题色、轻边框，主操作使用实色；自绘矢量图形可离线加载。
- 常用操作直接呈现；创建和修改进入短表单；备份和重置放到“更多”。
- 原版八个 Demo 的 `maker-product-v2-课程ID` 键与 v2 备份外壳保留。零花钱沿用原账本校验与存储键。
- 不在初始化时自动重写旧记录。异常 JSON 不被覆盖；导入先校验课程与结构，确认后提供导入前备份。移除支持当前页面会话内撤销。
- 新入口加载 `studio.js`、`studio.css` 和各课 `studio-app.js`。旧版文件暂留用于对照，但不再被新入口执行。
- `scripts/build-course-demos.py` 改为校验当前 Demo 的入口与依赖，防止旧的兄弟目录产品再次覆盖手工重做版本。

## 运行和边界

在仓库根运行 `python scripts/bootstrap-local-classroom.py --port 8766`，打开 `http://localhost:8766/courses/`。9 个入口仍在原课程页面中；没有新增学生公共门户。

这些是本地记录型课堂工具。旅行不提供实时价格/地图，屏幕工具不锁设备，习惯不推送系统通知，故事不直接调用在线大模型。AI 课程使用课堂已有的 AI 工具，把经过孩子判断的内容编辑回作品。

浏览器模拟手机与工程测试不能替代 9–14 岁孩子的真实试用。当前成果完成本地实现与验收，未提交 Git、未同步 GitHub、未部署 VPS；课程起始包和生产发布需要作为后续明确范围处理。
