# CODEXAI 儿童 AI 创作平台｜独立站与持续创作升级 PRD

**版本**：v1.0 · 2026-09-24
**状态**：方案已确认，分阶段开发与验证中。
**已有基础**：`codexai.site` 公开站、教师后台、学生后台、ZIP 上传与审核、家长作品链接和二维码、作品展。此前的多课程结构见《06-多课程平台产品方案与PRD》。

## 一、产品判断

网站应同时完成两件事：让第一次来的家长迅速理解“孩子会做出什么、怎么学、是否适合”，进而加微信或留下咨询方式；让已报名的孩子在课程之后仍有一个持续创作、更新和保存作品的空间。前者是对外的独立站，后者是仅向师生开放的创作平台；共享同一课程与作品资料，但入口、权限和页面表达分开。

现阶段不宜做成陌生孩子可注册的开放社区。正式学生账号由老师创建，作品先审核再分享。公开作品展是经过家长同意的精选案例，不是所有学生作业的自动列表。借鉴 Scratch 的教师建号与项目组织、Code.org 的教师控制分享机制，但不照搬评论、点赞、排名等社交功能。

### 已确定的业务选择

| 问题 | 决定 |
| --- | --- |
| 访客主要动作 | 加微信咨询，或填写简短表单等老师联系 |
| 谁能持续上传 | 老师创建账号的已报名学生；无需每次都报名新课 |
| 新作品默认可见性 | 学生本人和老师可在后台查看；审核后生成给家长的非公开分享链接；不自动进入作品展 |
| 公开作品展 | 老师线下取得家长同意、在后台登记凭据后，再手动公开 |
| 课程时间与价格 | 网站先展示课程内容和适龄说明；具体排期、价格咨询获取 |
| 作品保存 | 长期保留已发布版本和原始文件，提供备份、撤销分享和删除处理能力 |

**分享链接的含义**：拿到链接的人可以转发，因此“持链接可见”不能等同于“只有一位家长可见”。新链接应使用难猜的随机标识，不出现在作品展或站点索引中；老师可以撤销并重新生成。若未来要求严格限定某位家长，还需另做家长身份验证。

## 二、现状与缺口

| 方面 | 现在已有 | 主要缺口及影响 |
| --- | --- | --- |
| 首页 | 价值主张、九张课程海报、首课示范、课堂过程 | 缺明确的咨询入口、信任信息、课程详情与常见问题；外部渠道来的家长看完难以行动 |
| 课程 | 后台可创建半天课和营期课题 | 公开站只展示海报；课程目标、产出、适龄、流程、家长能做什么缺独立详情页；“课程方向”和“已开放”不够清晰 |
| 学生创作 | 账号、已分配课程、起始包、按课题交 ZIP、看反馈 | 无“自由创作”入口；无法在课后独立开新项目并长期迭代同一作品 |
| 教师管理 | 建班、分课、审核、发布、作品展开关 | 无咨询线索、自由创作审核队列、家长同意记录、分享链接撤销/重发、内容发布管理 |
| 家长交付 | 链接、二维码、添加桌面说明 | 缺集中易懂的手机操作指引及作品失效/换机时求助入口 |
| 作品展示 | 独立作品展与教师手动移除 | 当前发布流程默认加入作品展；移除只隐藏列表，直达链接仍有效，与新约定不符 |
| 长期运营 | 原 ZIP 和历史版本保留、备份工具 | 缺作品集组织、课程更新后公开站同步、咨询来源统计与内容维护节奏 |

其中“默认公开”必须先于新增推广处理：现有发布代码将普通新作品的 `listed` 设为公开；当前作品展接口返回数量为 0，但以后发布的作品仍可能自动展示。现有 `/projects/编号/课题/` 链接也不能靠移出作品展实现访问控制。

## 三、目标、边界与指标

**首版目标**：访客能看懂课程并完成咨询；已报名学生能在课程项目之外创建和更新自由作品；老师能审核、交付家长、管理公开展示；任何新学生作品都不会未经同意自动公开。

**建议观察的指标**：渠道访客到咨询的转化、有效咨询数和来源、课程详情到咨询点击率、已报名学生的二次创作比例、作品审核等待时间、家长链接首次打开成功率、公开作品同意记录完整率。先记录基线，再定目标值。

**首版不做**：陌生人自主注册、站内支付、社交评论/私信/排行榜、AI 自动审核代替老师、家长复杂账号体系。以后如业务需要再评估。

## 四、角色与信息架构

| 角色 | 主要任务 | 页面/能力 |
| --- | --- | --- |
| 访客家长/渠道人员 | 判断课程价值，咨询报名 | 首页、课程列表与详情、示范体验、精选作品展、教学方式与老师介绍、FAQ、咨询页 |
| 已报名学生 | 上课、课后继续创作、看反馈和作品 | 我的首页、我的课程、自由创作、我的作品、项目详情/版本/分享状态 |
| 老师 | 建班、经营课程、审核与交付、跟进咨询 | 课程内容、学生、审核队列、作品与同意管理、咨询线索、基础统计与设置 |
| 持链接家长 | 打开孩子作品、保存手机桌面、必要时求助 | 独立作品页、二维码、手机使用说明；无需登录 |

### 对外网站建议导航

首页｜课程与创作营｜孩子作品｜怎么上课｜常见问题｜咨询报名；右侧保留“学生登录”，教师登录放在页脚/登录页，避免家长导航被后台入口干扰。首页首屏应明确“9–16 岁、零基础、半天完成可在手机打开的小网页”，并提供两个清晰按钮：“咨询课程”与“体验示范作品”。

课程列表将**已开课程**与**未来课程方向**区分。每门已开课有文字化详情：适合谁、时长、解决的问题、孩子能自主决定什么、最终带走什么、课堂安排、是否需要电脑、家长如何收到作品、咨询入口。营期详情按天展示主题与成果，不凭海报暗示尚未开放的课程已经招生。

精选作品展展示作品名称、解决的问题、孩子的设计选择和可试玩链接；默认只用代号或经同意的昵称，不放真实姓名、照片、学校和联系方式。零作品时继续展示教师示范案例，明确标注“示范”，不冒充学生作品。

“怎么上课/关于”解释半成品起步、孩子主导的决策点、老师审核、手机交付流程和授课者真实背景；FAQ 覆盖零基础、设备、AI 工具、隐私、作品长期保存、手机离线和换机问题。页脚提供真实联系方式、隐私说明、作品展示与撤回说明。

## 五、关键需求与优先级

### P0：隐私规则和长期创作闭环

1. **修正默认公开**：新提交通过老师审核后，状态为“家长分享”，不进作品展。将分享链接改为难猜的独立地址；公开站不列出此类链接，也不将其纳入站点地图。老师可撤销/重发链接，撤销后旧地址不能继续打开。课程作品与自由作品都适用。
2. **旧链接迁移**：盘点现有已发链接和二维码。已交付家长的旧地址在迁移期间保留可用，并逐步改为跳转到新分享地址；涉及已公开作品先确认同意记录。迁移前做数据库与文件备份，不让家长收藏夹突然失效。
3. **自由创作**：已报名学生登录后可点击“创建作品”，填写标题、想解决的问题、类别及简短说明，上传静态网页 ZIP；不要求先分配课题。一个孩子可有多个自由作品，一个作品可多次提交版本。原来的课程交作业入口继续保留。
4. **统一审核**：自动检查 ZIP 的静态文件、大小、路径和入口页后，进入教师审核队列。老师预览、给反馈、退回或批准；新版本未获批准时，原家长链接继续显示上一个通过的版本。未通过的预览不对外开放。
5. **公开同意与撤回**：老师在后台登记家长同意的日期、渠道、确认人代号、适用作品/版本及凭据保存位置，再勾选“加入作品展”；没有记录时操作被阻止。家长撤回后，老师能立即从作品展移除，并按需要撤销分享链接。证明材料不公开给学生和访客。
6. **学生作品集**：学生能看到“课程作品”和“自由创作”两类、各作品状态、历史版本、老师反馈、家长分享地址；可申请老师重新审核/公开，不可自行绕过审核发布。

### P1：独立站咨询与信任内容

1. **首页与课程详情**：重写首屏与课程卡片，保留九张海报的视觉风格，但主要信息要变成可读文字；优先完成零花钱计划师详情，再按真实开课情况补其余课程与多日营。
2. **双咨询入口**：全站关键位置展示微信二维码和简短表单。表单建议只收家长称呼、微信号或手机号（二选一）、孩子年龄段、感兴趣课程、可选留言；自动记录入口页面与渠道码。提交后明确告知“老师联系”的下一步，不要求提供孩子真实姓名或学校。
3. **教师咨询台**：按新线索、已联系、已约体验、已报名、暂不跟进查看；支持备注与来源筛选。表单要有频率限制、防重复/垃圾提交、通知老师的可靠方式，以及导出/删除能力。咨询数据与学生公开作品资料分离。
4. **信任页**：展示真实授课者介绍、课堂照片或案例（取得相应授权后）、零基础课堂流程、家长评价（取得授权后）、作品如何保存和老师如何审核。没有真实材料时用明确的待补字段，不能编造背书。
5. **可发现性**：各课程有独立可读网址、标题和摘要；站点地图只纳入公开课程与公开作品，私密作品和后台排除。渠道海报/二维码链接带来源参数，统计只用于了解咨询来源。搜索可见性以页面质量和清晰结构为主，不承诺搜索排名。

### P2：运营效率与扩展

1. 教师可编辑对外课程介绍、FAQ、示范案例和咨询二维码；新建后台课题不会自动在前台宣传，须补齐详情并手动发布。
2. 教师首页展示待审作品、待跟进咨询、待补同意记录、近期发布成果；支持按班级、课题、自由作品筛选。
3. 作品按课题/类型/创作时间组织；营期可形成阶段作品集或结营页，仍沿用同一学生账号与审核规则。
4. 定期异地备份数据库、ZIP 和已发布文件，记录恢复演练；监控站点、上传和咨询表单的可用性。作品长期保留不等于不可撤销或删除。

## 六、核心流程

**获客**：渠道专属二维码 → 对应课程详情/首页 → 了解课程与示范 → 扫微信或填表 → 教师后台记录来源并跟进 → 确定报名后由老师创建学生账号。未报名访客不能上传。

**上课作品**：老师分配课程 → 学生下载起始包 → 制作并交 ZIP → 自动检查 → 老师预览与反馈 → 批准生成家长分享链接/二维码 → 家长在手机浏览器打开并添加到桌面。是否进入作品展是独立的后续动作。

**自由作品**：已报名学生登录 → 新建自由作品 → 填作品卡并交 ZIP → 自动检查/老师审核 → 分享给家长 → 继续提交新版本。学生可以在课后反复做新项目，不占用某节课程的作业位置。

**公开展示**：老师线下取得家长同意 → 后台登记 → 检查作品内容是否含个人信息与外部资源 → 选择展示版本与简介 → 加入作品展；家长撤回时立即下架并记录操作。

## 七、页面与交互要求

- **移动优先**：外部站主要为手机访问；首屏即可看到课程价值和咨询按钮，微信二维码有长按识别说明，表单在手机上可轻松完成。电脑端照顾渠道演示与教师操作。
- **公开与后台分层**：学生/教师登录是清晰的辅助入口；营销页不出现上传密钥、班级编号或后台术语。老师后台强调待办与状态，学生后台强调“继续创作”。
- **作品可解释**：作品卡不只给链接，还用一两句话说明“孩子要解决什么、自己改了什么”；教师示范与学生作品标识明确。
- **无障碍与性能**：文字不依赖海报图片传达，按钮有明确标签；海报压缩和延迟加载。表单错误能被读懂，长页面有清晰层级。
- **内容管理**：课程状态至少分“草稿/开放咨询/暂停/归档”；已发布作品更换版本不改变家长常用入口，撤销除外。

## 八、数据与权限要点

最少新增 `自由作品`、`作品版本`、`分享授权`、`公开展示同意记录`、`咨询线索` 五类数据。原班级、课程、课题、学生编号沿用。作品须区分“草稿/待审核/需修改/已批准/已撤销”，以及独立的可见性“仅后台/持链接分享/公开展”。审核状态不能直接推导公开状态。

上传作品只托管静态网页，不执行学生提交的服务器程序；维持文件类型、解压路径、容量、外链和脚本安全检查。学生只能查看自己的项目，老师按最小权限管理。公开页不得暴露学生登录凭据、真实身份或咨询资料。家长手机里记录的真实零花钱数据继续只留在该手机；网站应清楚告知换机和清缓存的影响。

由于网站服务器在日本，若新增家长联系方式、监护人同意记录等资料，需要在表单上线前确认隐私告知、保存位置、访问权限、保存期限和跨境处理适用要求；必要时请专业人士审核。家长同意的范围应明确到“上传使用”和“公开展示”，并支持撤回。法律合规要求不能用一个默认勾选框替代。

## 九、验收标准

1. 一位新访客从渠道二维码进入后，能在手机上找到适合的课程、体验示范，并完成微信咨询或表单提交；老师能看到来源与联系方式，重复提交不会造成大量垃圾线索。
2. 老师新建一名学生并分配课程后，学生既能交课程作业，也能独立创建至少两个不同的自由作品；同一自由作品能提交修订版。
3. 任一新作品获批后不会自动出现在公开作品展；家长专属链接能打开，未知编号无法推算其他孩子的分享地址；撤销后旧链接失效。
4. 没有家长同意记录时，后台不能把作品放到公开展；撤回后公开列表不再出现该作品。教师示范不计入学生作品数。
5. 20 人同场上传的目标场景下，页面给出清楚的成功/失败反馈，教师能筛出待审项；一次学生上传失败不影响其他人。该场景需在正式上线前做真实环境压力验证。
6. 已有家长作品链接在迁移后仍按计划可访问或获得可替换的新地址；旧版能回退，备份可恢复。手机添加桌面与离线使用仍需真实手机验收。

## 十、实施顺序与设计交付

1. **先修公开边界**：备份、梳理旧链接，修默认公开和新分享机制，补同意登记与撤销。期间保持现站正常服务。
2. **再做创作闭环**：自由作品数据、学生作品集、统一上传审核、教师队列和家长交付。
3. **然后升级独立站**：信息架构、首页/课程详情/咨询表单/信任页、课程内容管理和来源统计。
4. **最后完善运营**：营期展示、作品集策展、备份监控和报表。每阶段在桌面与手机验证，不一次性替换全部页面。

设计阶段可用 Sites 制作供评审的页面原型；正式动态能力继续由现有 VPS 承载。是否将公开前端迁往 Sites，应在设计确认后单独评估域名、登录与接口、缓存、回滚和国内访问体验；本 PRD 不改变当前部署。

## 十一、开始开发前需准备的真实素材

品牌/机构名称及一句话介绍、授课者真实履历、首批真正开放咨询的课程清单和详情、微信二维码及接待方式、家长常见问题、已获授权的作品和评价、隐私告知与家长展示同意记录模板。课程 PPT、正式班人数和助教安排仍由老师准备，不纳入网站开发交付。
